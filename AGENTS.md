# Project workflow

- New room features use the staged rollout in `docs/room-releases.md`: register a feature key, enforce `RoomReleases::allows` for server actions and use the room's server-provided feature list for UI. Verified OR partnered OR featured qualifies for three days of early access; official alone does not. This is per room, not an owner-wide entitlement. Keep existing public features public and ship security/correctness fixes normally.
- `tests`, `tmp` and `test-results` are temporary and must be absent after testing. Before editing or adding tests, run `node scripts/test-workspace.mjs prepare` to restore the existing suite from its archive outside the project. Use the npm test scripts or `composer test` for automatic archiving/cleanup; after manual testing use `node scripts/test-workspace.mjs clean`. Do not replace the archived suite with a partial new tests directory. Normal builds/site operation must not restore these folders.
